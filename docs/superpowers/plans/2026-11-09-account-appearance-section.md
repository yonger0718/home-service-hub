# Account Settings 外觀 Section (PR C2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the 外觀 section of 帳戶設定 as a preview plus a three-way source switch 上傳圖片 / 內建 logo / 文字＋顏色 with a 「目前顯示：…」 line, as its own component used on desktop inline and on phone inside the page sheet — the first section extracted out of `account-settings.ts` (#354).

**Architecture:** One new presentational component `app-account-look` (`components/accounting/account-settings/look-section/`) owns the preview, the `app-seg-toggle` source switch, the drop zone, the bundled logo grid and the text + swatch fields. It is stateless about the account: it receives `logo` / `icon` / `color` / `logoHash` / `accountId` / `busy` and emits `logoChange` / `iconChange` / `colorChange` / `upload(File)` / `remove`. The page keeps the form, the immediate image writes (`uploadAccountLogo` / `deleteAccountLogo`, the dirty-form invariant of spec "Image write keeps the dirty form") and the toasts. A pure helper `lookSummary()` gives both the component's 「目前顯示」 line and the phone row's value. The only visual state the component owns is which tab is open; it is re-derived from the data each time `accountId` changes and never writes to the form.

**Tech Stack:** Angular 21 standalone, signals, `ChangeDetectionStrategy.OnPush`; vitest via `cd frontend && npx ng test --watch=false --include=<glob>`; SCSS; existing `app-seg-toggle`, `app-account-icon`, `LayoutModeService`.

**Spec:** `openspec/changes/polish-reward-and-account-settings/specs/frontend-accounting-ledger/spec.md` — Requirement "Account settings page", bullet 外觀 and scenarios "Pick a logo", "Clear the logo", "Remove button only with an uploaded image", "Image write keeps the dirty form", "Upload on a new account"; `design.md` §D5. Precedence and limits come from `openspec/specs/frontend-accounting-ledger/spec.md` (account-logo-upload: uploaded image > bundled `logo` slug > `icon` emoji; PNG / JPEG / WebP, 5 MB). Artboards: `design_handoff_v3/design_refs/AccountSettingsDesktop.dc.html` (外觀 block: 64 px preview + 預覽 caption, `role=radiogroup` 圖示來源, dashed drop zone 「拖曳圖片到這裡，或 [選擇檔案] PNG / JPG / WebP · 5 MB 以內」, 56 px logo radios, 文字 input + 7 colour radios) and `AccountSettingsPhone.dc.html` (外觀 = one row 圖示 with the value 「內建 logo · 玉山 Pi」 and the hint 「上傳圖片、內建 logo 或文字＋顏色」). Where an artboard disagrees with the spec or the data model, the spec and the model win (the artboard's `maxlength="4"` on 文字 is NOT used: `icon` keeps 16).

## Global Constraints

- Copy verbatim: tabs `上傳圖片` · `內建 logo` · `文字＋顏色` (radiogroup aria-label `圖示來源`); drop zone `拖曳圖片到這裡，或` + button `選擇檔案` + limits `PNG / JPG / WebP · 5 MB 以內`; `移除圖片`; new-account hint `先建立帳戶，再上傳 logo`; grid first cell `無` (radiogroup aria-label `內建 logo`); text label `文字` (input aria-label `圖示`), swatch radiogroup aria-label `顏色`, custom input aria-label `自訂顏色`; preview caption `預覽`; the status line `目前顯示：` + `上傳的圖片` | `內建 logo · <label>` (`未知 logo` for a slug the bundled set does not know, as today) | `文字 <icon>` | `預設圖示` (empty icon). Phone row label `圖示`, hint `上傳圖片、內建 logo 或文字＋顏色`, value = the status text without the `目前顯示：` prefix.
- Data model unchanged: `AccountForm.icon` (string, ≤ 16 characters, `maxlength="16"` kept), `AccountForm.logo` (`string | null`), `AccountForm.color` (string, `''` = none; saved through today's `textOrNull`), `logo_hash` read-only from the detail. Switching tabs writes nothing. Precedence upload > logo > icon is what `app-account-icon` already renders; the status line follows the same order.
- Swatches: a new `ACCOUNT_COLOR_SWATCHES` in `frontend/src/app/theme/account-colors.ts` = the seven light `--app-series-N` values of `styles.scss` as stored hex (`#533afd` 靛紫, `#4f8f8a` 青綠, `#b7843f` 金棕, `#b9687e` 玫瑰, `#7e78a8` 薰衣草, `#5f7f98` 灰藍, `#8a93a3` 石墨), plus the custom `<input type="color">`. Hex comparison is case-insensitive; a stored colour outside the set marks the custom swatch.
- Image writes keep their behaviour: `uploadAccountLogo` / `deleteAccountLogo` are immediate, patch only `logoHash`, never touch the form or its baseline; the 5 MB client check and `logoUploadErrorMessage` toasts stay in the page. Upload is disabled (button `disabled`, drop ignored) while `accountId` is null or a write is in flight (`aria-busy`).
- Existing spec hooks keep these class names: `.logo-grid`, `.logo-opt`, `.logo-upload` (now the 選擇檔案 button), `.logo-remove`, `.logo-hint`, `.icon-input`, `.color-input`, `.bigicon`. Removed: `.logo-block`, `.logo-state`, `.logo-actions`, `.logo-pick` (the 選擇內建 logo button) — the tests that used them are rewritten in Task 2, none deleted without a replacement asserting the same behaviour.
- Breakpoint via `LayoutModeService.mode()`; tests force it with `TestBed.inject(LayoutModeService).set('phone' | 'panes')`. Phone: the 外觀 section is a `.set-card` with one `sheetRowButton` row (`'look'`), the control opens in the existing page sheet (focus trap, Escape, 完成, `restoreOverlayFocus` — no new sheet).
- Line icons only (`theme/line-icons.spec.ts`): the drop-zone arrow is inline SVG; no emoji in templates (the preview's emoji comes from `app-account-icon`). No bare Bootstrap grid class names (`theme/bootstrap-grid.spec.ts`): no `row` / `col` classes. No real account names, ids or amounts in fixtures. No new npm dependencies.

## Review Focus

1. 文字＋顏色 tab opened while an uploaded image exists: the preview must still show the upload and the status line must read 上傳的圖片; typing in 圖示 must change `icon` only (precedence kept) — test in Task 1.
2. New account (`/accounting/accounts/new`): 選擇檔案 disabled with the hint, a drop does nothing, 移除圖片 absent, the default tab is 文字＋顏色 — tests in Task 1 and Task 2.
3. A stored colour saved by MOZE in uppercase (`#4F8F8A`) must mark the 青綠 swatch; `#123456` must mark the custom swatch and show it in the colour input; picking a swatch must emit lowercase hex and dirty the form — tests in Task 1 and Task 2.
4. Phone sheet hosting the look block: Tab cycles through the seg toggle, the grid and the colour input without leaving the dialog; Escape returns focus to the 圖示 row; the row's value changes after a logo is picked inside the sheet — tests in Task 3.
5. The tab must not jump when data changes under the user: an upload finishing while 上傳圖片 is open stays there; 移除圖片 keeps 上傳圖片 open; navigating to another account re-derives the tab from that account's data — tests in Task 1 and Task 2.

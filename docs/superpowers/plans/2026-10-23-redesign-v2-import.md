## Decisions this plan makes

1. **One component, three types.** `ImportType = 'transactions' | 'dividends' | 'broker'` (`kind` signal becomes `type`); 交易 / 股利 keep `uploadCsv(kind, …)`; 券商對帳單 uses `uploadBrokerCsv(file, dryRun)` and renders `BrokerCsvImportResult` (`models/portfolio.model.ts:136-150`: `detected_broker`, `transactions`, `cash_flows`, `counts {created, skipped, rejected}`, `errors [{row_index, reason}]`). `components/portfolio/broker-import/*` is deleted; its spec intents move into `import.spec.ts` (dry-run renders rows + cash flows without a created count; commit shows counts and clears the file; row errors keep the file; unknown header → `manual`/none with the generic-CSV warning). Route `portfolio/import-broker` → `{ redirectTo: '/portfolio/import?type=broker', pathMatch: 'full' }`; the page subscribes to `route.queryParamMap` for its whole life (the sidebar link is `/portfolio/import` with no query and the component instance is reused), maps `?type=` with `typeFromQuery` (`broker` | `dividends` | `transactions`, default transactions) and writes the param back when the toggle changes (`router.navigate([], { queryParams: { type }, replaceUrl: true })`). The broker path does not send `name_overrides` and does not render the 確認股票代號 card (today's behaviour; `/imports/csv` is `import_transactions` and its `unresolved_names` are ignored there).
2. **Steps.** Component signals `committing = signal(false)` (set around the commit request) and `committed = signal(false)` (set on a commit response, cleared by 取消 or a new file); `step = computed(() => stepFor(!!result() || !!brokerResult(), committing(), committed()))`: a `.steps` strip 選擇檔案 → 預覽與確認 → 匯入並重算 with the current step highlighted and finished steps ticked; step 3 subtitle `寫入後自動重算`. After a successful commit the page stays on step 3 (strip on 匯入並重算, chip gone — `clearFile()` drops the file and the native input but keeps the committed result and its counts) showing the recalc panel until 取消 (full reset, `onClear()`) or a new file.
3. **檔案 card** (`app-bento` title 檔案): 匯入類型 `app-seg-toggle` (`ariaLabel="匯入類型"`, 交易 / 股利 / 券商對帳單; changing it clears result/overrides and re-previews when a file is present, as today's `onImportOptionsChange`), the 首列為欄位名稱 checkbox (hidden for 券商對帳單 — the broker parser detects its own header), hint line per type (交易/股利: `通用欄位格式（日期、名稱、買賣、股數、價格）` + `支援自動偵測：國泰證券`; 券商對帳單: `券商對帳單（交易＋現金流）`), the dropzone (unchanged behaviour) which on selection becomes `app-file-chip` (it already prints `已解析 N 筆`; the chip's count is the single row count) + a meta line `偵測格式：{format}` and two actions 更換檔案 (re-opens the picker) / 移除檔案 (= 取消). Detected format label: 交易/股利 from `detectedFormatLabel()` as today (`國泰證券` / `通用 CSV`), 券商對帳單 from `detected_broker` (`FIRSTRADE`, `IB`, … or `manual` with the warning `將以通用手動 CSV 解析`). A broker-format selector is never rendered.
4. **預覽 card** (shown when a result exists): count tags `解析 {parsed}` · `重複 {dup}` · `錯誤 {errors}` with **the wire rule** — 交易/股利: `parsed`; `dup` = `would_skip_duplicate` only when `csv_format === 'cathay' && dry_run` (the only path where the serializer's `would_*` numbers are live, `imports.py:100-101`, `broker_cathay_service.py:436-487`), else `skipped_duplicates`; `errors` = `errors.length` (parse errors are **not** in `parsed`, `import_service.py:750`); 券商: `transactions.length + cash_flows.length`, `counts.skipped`, `errors.length`. **When rows carry `status` (Task 1b, Option B)** the dup count is the number of `duplicate` rows instead. Grid 日期 / 股票 / 買賣 / 股數 / 價格 / 結果 (股利 swaps 買賣·股數·價格 for 股利金額 · 入帳日 as today); row result = `row.status` when present (`new` → 新增 neutral tag; `duplicate` → `重複 · 略過` neutral tag + `.dimmed` row; `unresolved` → 代號待確認 warning tag; `error` → 錯誤 danger tag), else the fallback derivation (錯誤 when `errors` has the `row_index`, 代號待確認 when the name is in `unresolved_names`, else 新增 — never an invented 重複). 券商對帳單 adds a second table 現金流 (日期 / 類型 / 金額 / 幣別) from `cash_flows`; both broker tables read cells through the existing `field(row, keys)` lookup, which checks `payload` first (rows are `{row_index, fingerprint, payload, status}`).
5. **需要修正的列 card** (when errors): one line per error `第 {row_index} 列 · {message|reason} · 此列會被略過`. Errors come from the 200 body (`result.errors`) **and** from an HTTP error body `{errors:[{row_index, reason}]}` / a string `detail` (today's `extractErrors`); in both cases the file stays selected.
6. **確認股票代號 card** (when `unresolved_names`): one block per name — title `{name} 的股票代號`, meta `{occurrences} 筆 · {sample_dates joined by 、}`, code input + 驗證代號 button (`verifySymbol`, existing status icons/texts), the 確認使用此代號 checkbox; behaviour unchanged from today's override rows (`setOverride`, `verifyName`, `toggleConfirm`, `pendingOverrideCount`).
7. **Footer:** 取消 (ghost; clears file, result, overrides; history/banner untouched), 重新預覽 (secondary; disabled without a file or while busy), 確認匯入 {N} 筆 (primary; `N = confirmCount(type, r)`: with `status` rows → the number of `new` rows; else 交易/股利 → `would_insert` only on a Cathay dry-run, otherwise `max(0, parsed − dup)` (errors are never subtracted: 解析 41 / 重複 3 / 錯誤 1 → `確認匯入 38 筆`, spec scenario); 券商 → `max(0, transactions.length + cash_flows.length − counts.skipped − tableErrors)` where `tableErrors` counts only errors whose `row_index` is in the rendered rows). Disabled only while busy or without a result — **not** for pending/unverified overrides: today's `commit()` keeps submitting after the `尚有代號未驗證` dialog and the backend returns `skipped_unresolved`; that dialog stays.
8. **Device-local history.** `ImportHistoryService` (root, `services/import-history.service.ts`): `attempts = signal<ImportAttempt[]>` loaded from `localStorage['hh-import-history']` (JSON array, newest first, max 10; `{ at: ISO, file, type, ok, created?, errors?, reason? }`), `record(attempt)`, `lastFailed = computed(() => attempts()[0]?.ok === false)`, `clear()`; `storage` event listener for other tabs; every read/write in try/catch (private mode). The page records an attempt on every **commit** outcome via `classifyCommit`: HTTP error → `ok: false, reason`; 200 with `created === 0` and `errors.length > 0` → `ok: false, errors`; 200 with `created === 0` and no errors (all duplicates) → `ok: true, created 0`; 200 with `created > 0` → `ok: true, created` even with row errors (partial writes are successes); dry-runs are not recorded.
9. **Banner.** At the top of the page in two distinct forms: (a) `history.lastFailed()` → `最近一次匯入失敗（{MM/DD HH:mm}）：{file} 有 {n} 列錯誤，整批未寫入。修正後重新上傳即可。` (or `…：{file}，{reason}，整批未寫入。…` for an HTTP failure) — the 整批未寫入 / nothing-written sentence appears **only** here, because a failed attempt is by definition `created 0`; (b) `recalcStatus().kind !== 'quotes' && state === 'failed'` (rows may have been written) → `最近一次匯入的重算失敗：{reason or current_step}`, no nothing-written sentence, with the recalc panel (Decision 12) visible beneath. Both use `.import-banner` (`--app-danger-soft` / `--app-danger` tokens if present, else the `--c-red` tokens the nav dot uses). (a) disappears when the next commit on this device succeeds; (b) when the recalc status is no longer failed.
10. **Nav dot.** `NavBadgeService` adds `inject(ImportHistoryService).lastFailed()` to the 匯入 dot condition (`services/nav-badge.service.ts:65-68`): dot when the recalc chain failed **or** the device's last attempt failed; label stays `最近一次匯入失敗`. `ImportHistoryService` injects nothing from the badge side (no cycle). The device flag clears on the next successful commit; the dot stays while `recalc.state === 'failed'`.
11. **Side column** (`panes`): `app-bento` titled `匯入後自動執行` (aside `aria-label` 匯入後會發生什麼) with three rows — 重算持股與損益 / `依新交易重建成本、已實現損益與當沖標記`; 抓取除權息事件 / `新股票的除權息會記為待收股利，需到股利頁確認收款`; 更新報價 / `回補收盤價，不含股利` — and `app-bento` 最近匯入 listing `attempts()` newest first: `{MM/DD HH:mm} · {成功|失敗} · {新增 n 筆 | n 列錯誤 | reason}` with a green/red dot (`--app-trend-positive`/`--c-red` tokens as the nav uses), file name beneath, `尚無匯入紀錄` when empty. Below `panes` (sheet + phone) the same two cards render under the footer.
12. **Step 3 / recalc panel.** The existing recalc status block (steps, deferred dividends, quote refresh, the `重算資料` button and polling) moves into the 匯入並重算 section and keeps every current behaviour and test intent (`import.spec.ts:39-91`: no duplicate recalc submissions, deferred historical amounts, quote-only run not labelled as a completed import, running quote status keeps a partial import). It is visible when `step() === 3`, or when the loaded status is `running` / `failed` / `partial`, or when `kind === 'quotes'` (the two existing on-load tests render it with no file).
13. **Header:** `app-page-header` keeps the nav title (匯入 CSV) with no actions; phone layout stacks the cards; the steps strip wraps.
14. **Copy (verbatim):** 匯入步驟; 選擇檔案 / 預覽與確認 / 匯入並重算 / 寫入後自動重算; 匯入類型, 交易, 股利, 券商對帳單; 首列為欄位名稱; `{n} 列 · 偵測格式：{format}`; 更換檔案, 移除檔案; 預覽; 解析 {n} / 重複 {n} / 錯誤 {n}; 新增 / 重複 · 略過 / 代號待確認 / 錯誤; 需要修正的列; `第 {n} 列 · {msg} · 此列會略過`; 確認股票代號; `{name} 的股票代號`; 驗證代號; 確認使用此代號; 取消 / 重新預覽 / 確認匯入 {n} 筆; 最近一次匯入失敗; 沒有寫入任何資料。; 匯入後會發生什麼 + the three pairs in Decision 11; 最近匯入; 成功 / 失敗; 新增 {n} 筆; {n} 列錯誤; 尚無匯入紀錄; 通用 CSV / 國泰證券 / `將以通用手動 CSV 解析`.
15. **Spec notes (Task 6):** rows carry a per-row `status` from the dry-run response (Task 1b; old responses without it fall back to 新增/代號待確認/錯誤 only); the history is device-local (`localStorage`, 10 entries); the device flag clears on the next successful commit on that device while the dot remains if the recalc chain is `failed`; dry-runs are not recorded; a partial commit (`created > 0` with row errors) counts as a success and never shows the nothing-written sentence; the broker type hides the header checkbox and the symbol-confirmation card; `/portfolio/import-broker` redirects (the routes spec expects the post-redirect URL and h1 `匯入 CSV`).
